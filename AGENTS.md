# AGENTS.md

Standalone DeepSeek Harness plugin repository (`dsh-session-emoji`). Development follows the dsh-plugin-guide skill and the official plugin contract; this file records repo-local decisions.

## Layout

- `src/index.ts` — function-plugin contract (`name`/`inject`/`Config`/`apply`; NO default export — the Loader unwraps `exports.default ?? exports`). Injects `settings` only. On the `0.1.7` settings contract the plugin's durable settings surface IS its own live Config: every former `session-emoji` namespace field is a `.volatile()` field on `Config` (pin lists, emoji maps, the recents list, organizer state, host policy), the profile entry id (`SETTINGS_ENTRY_ID`, the `cordis.patch.yml` row id) is the form namespace, and `apply` claims the generated-form presentation policy plus, under `enableLogBacking`, the log-backed projection reader. `enableLogBacking` alone stays ordinary Config — host-only, never a field of the old namespace.
- `src/pin-log.ts` — the `session/pin` event schema, the pure projection fold, and the `PinLogAppender` PRE-FLIGHT gate. The host's ability to carry the event is decided before the first write: the known event vocabulary (`KNOWN_SESSION_EVENT_TYPES`, the module's single `@deepseek-ai/dsh-session` value import) plus an ignorable-marker source probe (cached per process). Hosts where neither holds (`0.1.2-alpha.1`: envelope removed, fail-closed read on unknown types) get no append at all — the first write is where a poisoned log would start, so it never happens.
- `src/pin-core.ts`, `src/pin-store.ts`, `src/pin-controller.ts`, `src/navigator.ts` — framework-free state: two pin levels, per-row emoji (normalized against the shipped catalog), boards/tags/views, prune/reorder lifecycle. No cordis, no DOM.
- `src/emoji-data.ts`, `src/emoji-catalog.ts`, `src/emoji-picker.ts` — the checked-in generated catalog (Unicode 18.0 + CLDR zh/en annotations, see `THIRD_PARTY_NOTICES.md`), the lookup/search index over it, and the framework-free DOM picker both row paths share. `scripts/generate-emoji-data.mjs` regenerates the dataset by hand (`pnpm run emoji:generate`, cached sources under `.cache/`) — never in the gate, never over the network at runtime.
- `src/reorder-pump.ts` — the re-assertion guard (issue #4): one pass at a time (a list change landing during a pass collapses into a single re-check), moves applied sequentially against the live order, and a plan issued at most once per observed order — so the list-change echo of this client's own confirmed move cannot re-enter the reorder path. `connection/reset` re-arms it.
- `src/client.ts` — browser half: store + controller + overlay + row-slot glue + the shared emoji picker + slot contributions. Reads the host half's live Config form through `ctx.configForms.get(entryId)` (the `settingsScope` service is gone; `ConfigForm` is its documented successor), the `SessionId`/`WorkspaceId` brands from `@deepseek-ai/dsh-client-connection/client` (the removed `dsh-client-runtime` package must never reappear in this repo's imports or `dsh.client.inject`), and `connection` for the optional `session.setPinned` channel.
- `src/ui.ts` — slot UI. The session-header standard-kit seats (`sessionId`, `useProjection`) are typed as a LOCAL structural contract on the component props (the runtime merge package is gone; the runtime contract is structural). Type-only merges come from `dsh-client-ui-conversation`/`dsh-client-ui-sidebar`/`dsh-client-ui-layout`.
- `src/legacy-import.ts` — the rename's one-shot migration. When the former `session-pin` entry (the fork's pre-rename name, also the upstream plugin's id) is still installed, its pin lists, emoji maps, recents, and organizer state are folded into the new `session-emoji` namespace exactly once and only into fields that are still empty — a profile that already uses this plugin keeps its own state and a second run is a no-op. Without that entry the retired browser-local key (`LEGACY_STORAGE_KEY`, read-only) is the fallback. Both feeds must report `ready` before the plan is built, so a still-loading form can never be mistaken for an empty namespace.
- `src/row-slot.ts` — `sessions.row.action` adaptation: registration is deferred through `slots.inject` (the callback runs only if the build declares the slot). Current hosts (`0.1.2-alpha.1`) declare no such slot, so the wait stays pending, the overlay covers session rows, and nothing throws.
- `lib/` is committed on purpose. pnpm >=10 never runs a dependency's build scripts unless the profile allow-lists the package, and that allow-list key carries the resolved commit sha — so a GitHub-source install cannot build this plugin and instead ships the checked-in `lib/`. Run `pnpm run build` and commit it with every source change (`git add -f lib/` — it stays in `.gitignore` so tooling skips it); `ci.yml` fails when `lib/` is not committed or differs from a fresh build (`git ls-files --error-unmatch` + `git diff --exit-code -- lib`, safe because the build is byte-reproducible). The npm channel is unaffected: `pnpm pack`/publish builds and packs the fresh output.
- `scripts/build.mjs` — esbuild dual build; host externals (`schemastery`, `dsh-settings`, `dsh-session`) stay harness-resolved, the client bundle must contain no `@deepseek-ai/*` value import (purity check fails the build).

## Hard rules applied here

- **Pre-flight before write, never write-then-probe.** The log-backed append seam probes the host's event vocabulary and ignorable marker support before the first `session/pin` write; the result is cached per process (WeakMap keyed by the append implementation). A host that cannot carry the event receives zero appends and one warning; `allowUnmarked` is the deliberately dangerous opt-in.
- **Fail closed.** `enableLogBacking` defaults to `false`; on hosts that reject unknown event types the projection degrades to the settings cache — the durable state is never lost to a poisoned log.
- **Slot absence degrades, never throws.** Every slot contribution registers through `ctx.slots.inject` (deferred until declaration); the row-slot gate probes `slots.snapshot` and the DOM overlay covers session rows while the slot is undeclared.
- **Model-visible ⟺ logged.** The plugin is UI-only: nothing model-visible is added, no session events by default, no tokens on any request.
- **Waterfall discipline.** No waterfall listeners today; if one is added, passthrough MUST call `next()`.
- **Identity moves in one step; durable history stays readable.** Package name, plugin/entry id, locale namespace, slot contribution id, CSS prefixes, picker option ids, storage key, capability id, and repository metadata carry the current name only. The `session/pin` log-event name, the retired `session-pin` entry id, and the retired `dsh.session-pin.pinned` key are read-only compatibility seams (`src/legacy-import.ts`, `LEGACY_STORAGE_KEY`), and historical CHANGELOG entries are never rewritten.
- **Loud misconfiguration.** Invalid `Config` (negative `maxPins`, unknown enum members) fails `resolveConfig` at load.

## Checks

`pnpm run typecheck && pnpm test && pnpm run test:coverage && pnpm run lint && pnpm run check:readmes && pnpm run build && pnpm run verify:self-contained && pnpm run verify:artifacts && pnpm pack`

- `typecheck` resolves `@deepseek-ai/*` from the installed devDependencies (the `0.1.7-rc.2` line — the tag the plugin is verified against — plus `cordis ^4.0.3` and `schemastery ^3.18.3`, the first releases that export `Volatile`/`isVolatile` and `Schema.prototype.volatile`; this repo has no tsconfig paths). Host and client peers all carry the family baseline plus the `>=0.1.7-0 <0.2.0` clause.
- `verify:artifacts` also proves the built host ESM face imports under plain Node and that the client bundle carries the ModuleLoader handshake.
- The composition suite (`tests/composition.test.ts`) runs the BUILT entry through the real Loader in mkdtemp temp directories only.
- `scripts/verify-live.mjs` drives a real browser against a running `dsh web`: `DSH_AUTH_URL` (page-launch token) or `DSH_AUTH_COOKIE_FILE` selects the instance, `DSH_CHROMIUM` overrides the bundled browser, and results plus screenshots land in `verify-live/`. After a rebuild the instance has to be RESTARTED: the harness reconciles profile *config* live, but module *code* reload is opt-in/off, so the running host keeps its old half and the new client's field writes are refused (the row shows the emoji for a second, then rolls back). Also install from a fresh tarball path per install — `dsh plugin add` reports "Already up to date" when only the tarball's contents changed.

## Release

Publishing is tag-driven (no release script): bump `package.json`, stamp the CHANGELOG `[Unreleased]` section into a dated `## [x.y.z]` entry, re-run the full gate, commit, and push `main --follow-tags` with a `v<version>` tag (never force). `.github/workflows/release.yml` re-runs the gate, verifies the CHANGELOG names the tagged version, publishes to npm with provenance (authenticates with the `NPM_TOKEN` secret when set — required for the first publish of a new package name — otherwise expects a trusted publisher configured on npmjs.com; skips when the version already exists), and creates the GitHub Release.
