# Third-party notices

`dsh-session-emoji` ships **no third-party runtime code**: the built plugin bundles only this repository's own sources (`lib/index.js` host half, `lib/client.js` browser half), and it performs no network requests at runtime.

## Emoji dataset (`src/emoji-data.ts`)

The checked-in emoji catalog is generated by `scripts/generate-emoji-data.mjs` (`pnpm run emoji:generate`) from two Unicode Consortium sources, downloaded once into the git-ignored `.cache/` directory and consumed offline from then on:

| Source | Snapshot used | Copyright |
|---|---|---|
| [`emoji-test.txt`](https://unicode.org/Public/emoji/latest/emoji-test.txt) (Unicode Emoji Keyboard/Display Test Data) | Unicode 18.0, dated 2026-04-30 | © 2026 Unicode®, Inc. |
| [Unicode CLDR](https://github.com/unicode-org/cldr) emoji annotations (`annotations/en.json`, `annotations/zh.json`) | latest at fetch time | © Unicode, Inc. |

Both are distributed under the [Unicode License v3](https://www.unicode.org/license.txt). "Unicode" and the Unicode Logo are registered trademarks of Unicode, Inc. in the U.S. and other countries.

The generator keeps fully-qualified sequences, drops the `Component` and `Flags` groups and all skin-tone sequences, and joins each emoji with its CLDR English and Simplified-Chinese names and keywords. The resulting `src/emoji-data.ts` is therefore a derivative dataset of the two sources above; its contents remain subject to the Unicode License v3, while the plugin's own code stays Apache-2.0.

Regenerating the dataset is a deliberate, hand-run maintenance step: neither `pnpm run build` nor CI downloads anything, and the runtime never fetches the catalog.
